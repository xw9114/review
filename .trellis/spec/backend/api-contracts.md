# Knowledge structure API contract

## Scenario: Category → Topic → KnowledgePoint CRUD

### 1. Scope / Trigger

Use this contract whenever changing the first three levels of the knowledge hierarchy, their
FastAPI routes, Pydantic schemas, SQLAlchemy models, Alembic migrations, or frontend API client.

### 2. Signatures

Base URL: `/api/v1`.

```text
GET|POST              /categories
GET|PATCH|DELETE      /categories/{category_id}
GET|POST              /topics
GET|PATCH|DELETE      /topics/{topic_id}
GET|POST              /knowledge-points
GET|PATCH|DELETE      /knowledge-points/{knowledge_point_id}
GET                    /topics?category_id={category_id}
GET                    /knowledge-points?topic_id={topic_id}
```

Database migrations are applied with `alembic upgrade head`. The application must never create
production tables with `Base.metadata.create_all()`.

### 3. Contracts

Create payloads:

```json
{"name":"ROS2","description":"Robot Operating System 2"}
{"category_id":1,"name":"QoS","description":"Quality of Service"}
{"topic_id":1,"name":"Reliability","description":"Delivery reliability"}
```

`slug` is optional on create and generated by the service. Read responses add `id`, `slug`,
`sort_order`, `created_at`, and `updated_at`; knowledge points also add `is_active`.

PATCH accepts any subset of the corresponding editable fields. DELETE returns `204` with no
body. Deleting a category cascades to topics and knowledge points; deleting a topic cascades to
knowledge points.

Environment contract:

| Key | Consumer | Rule |
| --- | --- | --- |
| `DATABASE_URL` | backend, Alembic | SQLAlchemy URL; never exposed to the browser |
| `CORS_ORIGINS` | backend | Comma-separated exact browser origins |

### 4. Validation & Error Matrix

| Condition | Status | Body/assertion |
| --- | --- | --- |
| Valid create | `201` | Complete read model |
| Valid read/update | `200` | Complete read model |
| Valid delete | `204` | Empty body |
| Missing parent or record | `404` | `error.code == "not_found"` |
| Duplicate name/slug in scope | `409` | `error.code == "conflict"` |
| Missing/invalid field | `422` | FastAPI validation detail |
| Database unavailable on `/health` | `5xx` | Container health check fails |

Uniqueness scope is global for categories and parent-local for topics and knowledge points.

### 5. Good / Base / Bad Cases

- Good: create ROS2, create QoS under ROS2, create Reliability under QoS, then filter children.
- Base: lists are empty and return `[]`; descriptions may be null/empty.
- Bad: create a Topic with `category_id=999`; return `404` without inserting a row.
- Bad: create two ROS2 categories; the second returns `409` and the transaction is rolled back.

### 6. Tests Required

`backend/tests/test_knowledge_structure_api.py` must assert:

- the complete create/read/filter/update/delete round trip;
- database cascade behavior after deleting a category;
- duplicate conflict response and stable error code;
- missing-parent rejection.

Run `backend/.venv/Scripts/python -m pytest -q` on Windows or the equivalent venv command.

### 7. Wrong vs Correct

#### Wrong

```python
@router.post("/topics")
def create(payload):
    return db.add(Topic(**payload))  # route owns business rules; parent is not validated
```

#### Correct

```python
@router.post("", response_model=TopicRead, status_code=201)
def create_topic(payload: TopicCreate, db: DbSession) -> TopicRead:
    return service.create_topic(db, payload)
```

Routes validate transport contracts; `app/services/knowledge_structure.py` owns parent checks,
slug normalization, commits, rollbacks, and domain errors.
