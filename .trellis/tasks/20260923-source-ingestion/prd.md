# 日序资料导入 MVP

## Goal

打通“日序笔记同步 → 资料收件箱 → 人工归类 → 创建知识点”的第一条可用闭环，
同时保留来源、内容哈希和处理状态，为后续 Crawl4AI、Embedding 与模型处理提供统一入口。

## Requirements

- 日序提供仅供服务间调用的、Bearer Token 保护的笔记快照接口。
- 知识系统通过可配置的日序接口同步 `kind=note` 的文字笔记。
- 以 `(provider, external_id)` 幂等更新，并以标准化内容 SHA-256 识别内容变化。
- 新资料进入 `pending`；用户可以接受或忽略；来源消失标记为 `stale`，不删除知识点。
- 接受资料时必须选择现有主题，可编辑知识点名称与描述。
- 创建知识点与来源关系必须在同一数据库事务中完成。
- 提供资料收件箱页面和同步、接受、忽略操作。
- 日序不可用、未配置、响应格式错误时返回稳定错误码，不损坏现有资料。

## Acceptance Criteria

- [ ] 首次同步导入日序笔记并返回 created/updated/unchanged/stale 计数。
- [ ] 重复同步相同快照不会创建重复资料。
- [ ] 修改过的笔记更新内容哈希，并重新进入待整理状态。
- [ ] 缺失的远端笔记标记为 stale，已有知识点保持不变。
- [ ] 接受待整理资料后创建知识点与来源关系，重复接受返回冲突。
- [ ] 忽略资料后可通过状态筛选查看。
- [ ] 前端可完成同步、筛选、主题选择、接受和忽略。
- [ ] 后端测试、前端 lint 和生产构建通过。

## Technical Notes

- 当前是单用户系统；服务间认证使用 `NOTEBOOK_API_TOKEN`，不得暴露给浏览器。
- 日序数据量较小，MVP 使用全量快照而非增量游标；编辑检测依靠内容哈希。
- 图片附件仅保留扩展字段，本轮不复制二进制文件。
- AI 默认关闭；本轮不向任何第三方传输日记内容。
