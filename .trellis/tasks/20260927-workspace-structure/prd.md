# 工作区结构优化

## Goal

用户要求“继续优化结构”。先检查已上线的资料、草稿、知识与复习组织方式，减少入口重复和认知负担，保持原有数据、主题层级和人工最终审核规则。

## Known context

- 资料收件箱、订阅源、草稿审核、知识详情、复习均已实现；正文补充阶段已上线。
- 上轮线上为 107 条待整理资料、6 个知识点、1 份未批准草稿。
- 当前界面是暖白/橄榄绿风格；不新增外部服务或重做技术栈。

## Temporary interpretation

优先理解为页面信息结构与操作流程，并同步收敛相应重复组件。实现前检查用户是否更偏重代码或知识层级。

## Open preference

“结构”优先指页面与操作流程，还是代码模块，或知识领域/主题层级？

## Frozen scope

默认按页面与操作流程推进；用户若回复另一优先项，再调整后续范围。本轮只改前端导航与收件箱，不重做首页，不迁移数据库。

- 导航按工作台、收集与整理、知识与复习、来源管理分组，标签/图标/地址统一配置；保留六个原路由与移动端入口。
- 收件箱增加标题/来源/作者搜索及按来源筛选，列表高度受控，显示筛选数量；无匹配不能残留可操作旧详情。
- 选择资料/状态更新 URL，刷新继续当前资料；读取失败与空队列分开，允许明确重试。
- AI 起草是主入口，手动整理作为可展开备选；两个流程共享归属选择，不自动生成/批准。
- 手动字段未保存时，切换资料/状态、会重置选择的筛选及刷新操作需要确认；正文补充与手动编辑避免相互覆盖。
- 拆分列表、相关性、决策面板及状态编排，沿用现有 API 与富文本组件。

选择局部组件拆分而非整体重写；不引入状态库、UI 库或新的服务。主题和领域仍由用户管理。

## Requirements

- 查找重复入口、页面职责混杂与资料量变大后的选择问题。
- 现有链接、数据和操作语义向后兼容；不自动生成或批准。
- 不擅自移动、重命名或删除用户的领域、主题、资料与知识点。

## Acceptance

- [x] 冻结具体范围，并记录与现有结构的问题对应关系。
- [x] 所改流程与深链接、错误/空状态、移动端通过回归。
- [x] lint、类型检查、构建及相关测试通过。
- [x] 文档更新，安全备份部署后验证线上只读状态。

## Out of scope

新付费服务、Embedding、自动审核、原站 403 绕过、未经确认的知识层级迁移。
